## Global Constraints

- Default symbol: `"HYPE"` (`HYPE-PERP`), direction: `"long"`, range: `55.0` to `65.0`, `grid_count`: `30`, `amount_per_grid`: `1000.0` USDC.
- All entry and exit orders MUST use Maker (`post_only = true`, `TimeInForce::Gtc`), and exit orders MUST use `reduce_only = true`.
- Private key MUST be loaded from environment variable (`HYPERLIQUID_PK` or `PRIVATE_KEY`).
- Push repository to `git@github.com:mev751/grid-hype.git`, compile `x86_64-unknown-linux-gnu` via GitHub Actions, and deploy binary + `config.toml` to `box:/home/emc/grid-hype`.

## Review Focus

- Hyperliquid perpetual price rounding: prices must obey both `<= 5` significant figures and `<= (6 - sz_decimals)` decimal places; violating this causes exchange order rejection.
- Maker post-only crossing protection: for a Long Buy order at $P_i$, if current best ask $\le P_i$ (or for a Sell exit at $P_{i+1}$, if current best bid $\ge P_{i+1}$), submitting a `post_only` order immediately crosses and gets rejected; the grid engine must only submit when the price is strictly on the Maker side of the book and retry on subsequent ticks if rejected.
- Partial vs full fills: only transition a slot from `EntryWorking` to `ExitWorking` (or `ExitWorking` to `Idle`) when the order reaches `Filled` status (or accumulate filled quantity and place exit on full fill).
- Invalid configuration bounds (`lower_price >= upper_price`, `grid_count == 0`, `amount_per_grid <= 0.0`) must be rejected at startup with clear errors.
- Cloid (ClientOrderId) mapping: Hyperliquid requires 128-bit hex `cloid` (`0x` + 32 hex chars) or Nautilus `ClientOrderId` mapped consistently so fill/order status updates resolve back to the exact grid slot index.
